3. Переменные окружения и секреты
(Список имен без значений, передаются в сервис app через docker-compose.yml)

MONGODB_URI — строка подключения к базе данных
NEXTAUTH_SECRET — секрет для подписи сессий Auth.js
AUTH_SECRET — секрет для Auth.js v5
AUTH_TRUST_HOST — флаг доверия к хосту Nginx
AUTH_URL — публичный адрес приложения (HTTPS)
NEXTAUTH_URL — публичный адрес приложения (HTTPS)

4. Команды для запуска и остановки

Запуск проекта (сборка образов и старт в фоне): docker compose up --build -d
Остановка проекта (контейнеры удаляются, данные MongoDB сохраняются в томе): docker compose down
Просмотр логов: docker compose logs -f app

6. Ошибки, возникшие при выполнении работы, и способы их устранения

1. Ошибка Failed to fetch 'Inter' from Google Fonts при сборке Docker.
Решение: Next.js не мог скачать шрифты из интернета внутри контейнера. Заменили next/font/google на next/font/local, скачали файлы .ttf и положили их в src/fonts.

2. Ошибка CredentialsSignin при попытке входа в систему.
Решение: В docker-compose.yml добавили переменные AUTH_URL=https://devflow.localhost и AUTH_TRUST_HOST=true, чтобы Auth.js правильно определял домен за прокси.

7. Что нужно изменить для публикации на реальном сервере?

1. Сервер: Арендовать VPS (например, Timeweb, Selectel) с операционной системой Ubuntu.
2. Домен: Купить домен (например, devflow.ru) и настроить A-запись в DNS на IP-адрес сервера.
3. Сертификаты: Заменить локальные сертификаты mkcert на настоящие от Let's Encrypt (получить через Certbot).
4. Безопасность: Убрать 127.0.0.1 в docker-compose.yml (чтобы Nginx слушал внешние запросы) и настроить файрвол (UFW).
5. Секреты: Передавать реальные пароли и ключи через переменные окружения сервера, не хранить их в репозитории.
6. CD: Настроить GitHub Actions для автоматической сборки и доставки обновлений на сервер.
